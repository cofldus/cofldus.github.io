목표

자음·모음 치환, 받침 탈락 등 의도적 난독화로 필터를 우회하는 악성 리뷰를 원형 한글로 복원, 콘텐츠 모더레이션 신뢰도 향상

역할

노이즈 패턴 분석 · Seq2Seq 복원 모델 설계 및 학습 · 음소 토크나이저 커스터마이징 · 평가 파이프라인 구축

01

문제 정의 및 접근

야민정음(시각 유사도 기반 변형: '머 → 뫄')과 음운 오류(발음 유사 변형: '됩니다 → 됩니당')는 복원 방향이 근본적으로 다릅니다. 전자는 자모 그래픽 매핑 규칙이, 후자는 음성 전사 역변환이 필요합니다. 단일 모델은 두 방향 사이에서 최적점을 찾지 못해 출력이 불안정해집니다. 문제를 '모델 성능 부족'이 아닌 '태스크 정의 오류'로 재진단하고, 유형 분류 → 전용 복원 분기로 구조 자체를 바꿨습니다.

02

기술 선택 근거

01

분기 설계 vs 단일 seq2seq 모델

야민정음은 자모의 시각적 유사성('ㅎ → 흐'), 음운 오류는 발음의 음성적 유사성('됩니다 → 됩니당')이 변형 기제입니다. 두 방향은 복원에 필요한 지식 공간이 달라, 단일 모델이 같은 파라미터로 둘을 동시에 처리하면 손실 함수가 서로 상충해 불안정한 출력이 나왔습니다. 분류기로 유형을 먼저 판별하고 전담 모델로 라우팅하자 각 모델이 한 방향에 집중할 수 있었습니다.

02

JAMO 전처리 vs 기본 BPE 토크나이저

'뫄'처럼 야민정음으로 변형된 자모는 한국어 BPE 어휘에 없거나 OOV로 처리돼 [UNK]가 됩니다. 토크나이저 단계에서 정보가 유실되면 그 이후 어떤 모델을 써도 복원이 불가능합니다. 자음·모음을 초·중·종성으로 분리하면 변형된 자모도 기존 어휘 조합으로 표현되어 토큰 손상 자체를 막을 수 있었습니다.

03

KoELECTRA 분류기 vs 규칙 기반 분기

야민정음과 음운 오류가 동일 문장에 혼재하거나 경계가 모호한 경우가 많았습니다. 규칙으로 분기하면 예외 케이스를 열거하는 데 공수가 집중됩니다. KoELECTRA는 문장 전체 문맥을 보고 판별하기 때문에 혼합 케이스에서 규칙보다 안정적이었습니다.

03

핵심 구현 내용

01KoELECTRA Noise Classifier로 입력 유형 판별 후 야민정음·음운오류 전용 KoBART 모델로 분기 처리
02핵심 선행 과제: BPE 토크나이저가 야민정음 자모를 분해 실패 → JAMO(초·중·종성) 전처리로 토큰 손상 원천 차단
03BERTScore 0.9812 · CER 0.0426 달성, 분기 설계 도입 전 베이스라인 대비 +5.6%p 개선
04

실험 로그 — 시행착오 기록

R1

학습 데이터를 늘리면 단일 모델도 두 노이즈 유형을 동시에 안정적으로 처리할 수 있다

단일 유형 수치는 소폭 개선됐지만, 야민정음과 음운 오류가 혼재하는 실제 문장에서는 여전히 불안정했다. 데이터 문제가 아니라 구조 문제였다.

→ 데이터 증량만으로는 혼합 노이즈 대응이 근본적으로 불가능; 아키텍처 분리로 방향 전환
R2

문자 정보를 보강(Char-CNN)하면 그래픽 노이즈 복원이 개선된다

혼합 케이스와 그래픽 오류에서 여전히 실패했다. 보조 신호를 추가해도 단일 모델이 복원 방향을 판단하는 문제는 해결되지 않았다.

→ 입력 표현 보강이 아닌, 판단 자체를 분리하는 구조가 필요
R3

자모 분리(JAMO) 입력으로 야민정음 복원 정확도를 높일 수 있다

형태 복원은 강화됐지만, 의미 공간이 희박해져 긴 입력에서 원문과 무관한 새 문장을 생성하는 부작용이 발생했다.

→ JAMO 전처리는 아키텍처 분리의 전제조건으로, 단독으로는 오히려 품질이 저하될 수 있음
R4

KoELECTRA 분류기로 노이즈 유형을 먼저 판별하면 전담 모델 라우팅이 가능하다

분류기 + 경로 분기 구조에서 가장 안정적인 출력을 얻었다. 각 모델이 한 방향에만 집중하자 손실 함수 상충이 사라졌다.

→ 분기형 구조 확정 채택. BERTScore 0.9812, CER 0.0426 달성
R5
✓ 최종 채택

프롬프트보다 special tag로 유형을 내재화하는 것이 운영상 더 낫다

일부 케이스에서 운영 복잡도가 줄었지만, tag 의미 학습 품질이 통합 구조 전체의 핵심 변수가 됐다.

→ Tag 품질 관리가 분기형 구조의 실질적 병목임을 확인
05

현장에서 부딪힌 문제

01기본 난독화와 야민·그래픽형이 한 문장에 동시에 섞이면, 단일 모델은 어느 복원 전략을 먼저 적용할지 일관되게 결정하지 못했다.
02자모 분리 입력은 형태 복원에 유리했지만, 의미 공간이 희박해져 긴 입력에서 새로운 문장을 만들어내는 부작용이 있었다.
03프롬프트는 즉각적인 제약 효과가 있었으나 토큰을 소모하고 긴 리뷰에서는 오히려 집중력 저하처럼 작동했다. 최종 통합 구조는 프롬프트를 제거하고 학습 내재화를 택했다.
04EOS 이후 과생성이 모델 학습만으로 해결되지 않아, 입력 문장 수 기준 출력 제한 Lock과 1.3배 초과 시 강제 컷 규칙을 후처리로 추가했다.
06

배운 점

성능 지표가 오르는 것과 모델이 실제로 '이해'하는 것은 다르다는 사실을 이 프로젝트에서 가장 크게 배웠다. 데이터를 3배 늘리면 성능은 오르지만, 모델이 어떤 판단 근거로 복원하는지는 블랙박스 그대로였다. 야민정음과 기본 난독화가 한 문장에 섞이면, 단일 seq2seq 모델은 어느 규칙을 먼저 적용할지 일관되게 결정하지 못했다. 이 문제는 데이터나 학습법이 아니라 아키텍처 설계에 있었다. 모델 하나에 판단 책임을 모두 몰아준 것 자체가 오류였다. Classifier가 노이즈 유형을 먼저 분리하거나, special tag로 복원 의도를 의미 공간에 녹여 주입하는 방식, 어느 쪽이든 '판단 책임을 분산하는 구조'가 핵심이었다. 프롬프트와 데이터로 풀 수 없는 문제가 있고, 그것은 아키텍처를 바꿔야 풀린다.
