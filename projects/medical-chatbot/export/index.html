01 · 문제 정의

Naive RAG의 구조적 한계—단일 벡터 검색은 전문 의학 용어의 Recall 상한이 낮고, 검색된 문서 전부를 컨텍스트에 넣으면 LLM이 노이즈에 흔들린다—를 2단계 아키텍처로 정밀 해소했습니다. BM25가 용어 매칭 정확도를, FAISS가 의미적 유사성을 보완하고, bge-reranker가 최종 후보를 질문-문서 정합성 기준으로 Top-5로 압축해 LLM이 받는 컨텍스트 품질을 최대화했습니다. 5.5만 건 전문 의학 JSON(약 2.2억 토큰)을 처리한 코퍼스 기반 시스템입니다.

핵심 구현
01하이브리드 검색 설계: BM25(k=20, 용어 매칭) + FAISS(k=20, 의미 검색) 병렬 수행으로 Recall 상한 제거
02BAAI/bge-reranker-v2-m3 재순위: 40개 후보→Top-5 압축으로 LLM 컨텍스트 노이즈 최소화
03ReRanker 전후 비교: 객관식 정확도 +0.04, 서술형 BERTScore +0.16 향상, 단일 벡터 RAG 대비 명확한 개선
02 · 기술 선택 근거
BM25 + FAISS 하이브리드 vs 단일 벡터 검색
'폐색전증의 D-dimer 기준치'처럼 전문 의학 용어는 의미 임베딩 공간에서 일반 단어와 거리가 좁아 벡터 검색만으로는 Recall 상한이 낮습니다. BM25는 정확한 용어 매칭을, FAISS는 의미적 유사성을 각자 담당하도록 역할을 분리하고 결과를 병렬로 합산했습니다. 어느 한쪽만 쓸 때보다 Recall 커버리지가 눈에 띄게 올라갔습니다.
bge-reranker vs 단순 Top-K 절삭
BM25+FAISS로 40개 후보를 뽑은 뒤 전부 LLM 컨텍스트에 넣으면 관련 없는 문서가 섞여 답변이 흔들렸습니다. Reranker는 질문과 각 문서를 교차 인코딩해 정합성을 재평가하기 때문에, 단순 점수 기반 Top-K 절삭보다 노이즈 문서를 정확히 걸러냅니다. Top-5로 압축했을 때 BERTScore +0.16이 나왔고, Top-10에서는 개선폭이 절반 이하였습니다.
EXAONE-3.5 vs GPT-4
5.5만 건 의학 데이터를 반복 호출하는 환경에서 GPT-4 API 비용은 현실적이지 않았습니다. EXAONE-3.5는 한국어 의료 도메인 학습 비중이 높고 로컬 추론이 가능해 코퍼스 규모 실험에 적합했습니다.
03 · 실험 로그
M1
단일 FAISS 벡터 검색으로 전문 의학 용어 Recall을 충분히 확보할 수 있다
'폐색전증 D-dimer 기준치'처럼 의학 전문어는 임베딩 공간에서 일반 단어와 거리가 좁아, 벡터 검색만으로는 관련 문서를 놓치는 경우가 많았다.
→ BM25(정확 용어 매칭)와 FAISS(의미 유사성)를 병렬로 실행하는 하이브리드 구조로 전환
M2
40개 후보 문서를 전부 컨텍스트에 넣으면 LLM 답변 품질이 올라간다
관련 없는 문서가 섞이면 LLM이 노이즈에 흔들려 오히려 답변이 불안정해졌다. 컨텍스트 길이가 늘어날수록 정합성이 떨어졌다.
→ bge-reranker로 질문-문서 교차 인코딩해 Top-5로 압축. BERTScore +0.16 확인
M3
Top-10으로 압축해도 Top-5와 성능 차이가 없을 것이다
Top-10에서의 BERTScore 개선폭이 Top-5 대비 절반 이하였다. 컨텍스트 크기가 클수록 노이즈 영향이 더 강하게 작용했다.
→ Top-5가 품질·속도 균형의 최적점으로 확정
