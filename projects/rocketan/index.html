목표

강의 영상·자료 업로드만으로 퀴즈·학습 가이드를 자동 생성, 강사의 반복 출제 시간을 RAG 파이프라인으로 완전 자동화

역할

RAG 파이프라인 전체 설계 · FAISS 청크 전략 실험 · LangChain RetrievalQA 체인 구현 · 재현성 확보를 위한 캐싱 레이어 개발

01

문제 정의 및 접근

강의 영상과 자료를 업로드하면 핵심 개념 퀴즈와 학습 가이드를 자동으로 생성하는 시스템입니다. 강사가 수업 자료를 반복 정리·출제하는 데 소요하는 시간을 RAG 파이프라인으로 자동화했습니다. FAISS 벡터 검색과 LangChain 기반 체인 설계로 강의 맥락을 정확히 반영한 문제·해설을 생성합니다.

02

기술 선택 근거

01

RAG vs Fine-tuning

강의 자료는 수업마다 완전히 달라집니다. Fine-tuning은 새 강의마다 재학습이 필요해 운영 비용이 기하급수적으로 늘어납니다. RAG는 FAISS 인덱스를 교체하는 것만으로 새 강의에 즉시 적응할 수 있어 업데이트 비용 없이 도메인을 바꿀 수 있다는 점이 결정적이었습니다.

02

FAISS 단독 의미 검색

강의 자료는 전문 용어보다 개념 흐름이 중요합니다. BM25 키워드 검색은 표면 단어가 없는 관련 문단을 누락시키는 반면, FAISS 의미 검색은 맥락이 연결된 단락을 함께 검색해 퀴즈 문항의 완성도가 높았습니다.

03

LangChain RetrievalQA 체인

직접 프롬프트를 조립하면 검색 결과 개수나 순서가 바뀔 때마다 프롬프트 전체를 수정해야 했습니다. LangChain 체인은 검색 결과 삽입·프롬프트 템플릿 관리를 추상화해, 퀴즈·요약·가이드 등 여러 기능을 일관된 구조로 유지할 수 있었습니다.

03

핵심 구현 내용

01강의 문서 → FAISS 벡터 인덱싱 → 관련 청크 검색 → LLM 퀴즈·해설 자동 생성 파이프라인 구축
02LangChain RetrievalQA 체인으로 강의 맥락 기반 객관식·서술형 혼합 문제 생성, 난이도 조절 프롬프트 설계
03학습 가이드 자동 요약: 핵심 개념 추출 → 마인드맵 구조 텍스트로 재구성, 수강생 복습 효율 개선
04

실험 로그 — 시행착오 기록

RK1

청크 크기를 크게 하면 LLM이 더 많은 맥락을 보게 되어 문항 품질이 올라간다

청크가 커질수록 LLM이 핵심 개념을 찾지 못하고 무관한 내용을 섞어 문항을 생성했다. 청크 하나의 응집도를 높이는 것이 크기를 늘리는 것보다 효과적이었다.

→ 청크 크기 512 → 256 토큰으로 축소, overlap 32 토큰으로 문단 경계 유지
RK2

모든 강의 문서를 하나의 FAISS 인덱스로 통합하면 관리가 쉽다

다른 강의 자료끼리 의미가 유사한 청크가 검색에 혼입돼 엉뚱한 강의 내용으로 퀴즈가 생성되는 오염이 발생했다.

→ 강의별 독립 인덱스로 분리해 수업 단위 네임스페이스 관리 구조로 전환
RK3
✓ 최종 채택

퀴즈 난이도를 LLM이 자유롭게 판단하면 자연스러운 분포가 나온다

LLM이 항상 중간 난이도로 수렴하는 경향이 있었다. 쉬운 문항과 어려운 문항이 거의 생성되지 않아 학습 단계별 활용이 불가능했다.

→ '기초 확인·심화 적용·추론' 3단계 난이도를 프롬프트에 명시적으로 지정하는 구조화 프롬프팅 도입
05

현장에서 부딪힌 문제

01강의 PDF 파싱 시 표와 수식이 깨져 의미 없는 기호 열이 됐다. PyMuPDF 대신 레이아웃 분석을 지원하는 pdfplumber로 교체하고, 수식 포함 셀은 플래그를 달아 퀴즈 생성 대상에서 제외했다.
02동일한 질문에 매번 다른 퀴즈가 생성돼 강사 검토·재활용이 불가능했다. temperature를 0.3으로 낮추고 동일 청크 결과를 캐싱하는 레이어를 추가해 재현성을 확보했다.
03학습 가이드 요약이 강의 자료를 단순 반복하는 수준에 머물렀다. '핵심 개념 → 이유·원리 → 예시' 순서로 재구성하도록 프롬프트 구조를 명세화하고 출력 형식을 JSON으로 강제했다.
06

배운 점

RAG의 품질은 검색 모델보다 청크 설계에 달려 있다는 것을 배웠습니다. 더 좋은 임베딩 모델을 탐색하는 것보다 청크 크기와 경계 설정을 바꿨을 때 문항 품질이 가장 크게 달라졌습니다. LLM은 좋은 컨텍스트를 주면 알아서 잘 하지만, 나쁜 컨텍스트에서는 프롬프트를 정교하게 짜도 한계가 있었습니다. 또한 자동화 시스템에서 재현성 확보가 실제 사용률에 직결된다는 것을 실감했습니다. 결과가 매번 달라지면 강사가 신뢰하지 않고, 신뢰받지 못하는 도구는 사용되지 않습니다. 기술 완성도보다 사용자가 믿고 쓸 수 있는 일관성이 실용 시스템의 핵심 조건입니다.
